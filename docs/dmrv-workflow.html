6Freeze · Pin · Anchorตอน Register: server ผนึก content_hash → pin เอกสาร PDD ต้นฉบับขึ้น IPFS → เบราว์เซอร์เซ็น Registration VC (กุญแจไม่ออกจากเครื่อง) → anchor ลง HCS topic ของโปรเจกต์
8ขคำนวณซ้ำอิสระData-check ฝั่ง VVB ใช้ข้อมูลดิบชุดเดียวกับผู้ยื่น — สองฝั่งเห็นเลขตรงกันเสมอ ไม่มีใครแก้กลางทางได้
11บันทึกสาธารณะToken mint เป็นธุรกรรมจริงบน Hedera testnet + audit log ภายในต่อกันเป็น hash-chain ตรวจย้อนได้ทุกการกระทำ

เส้นทางความน่าเชื่อถือ (Trust Chain) — ตรวจย้อนได้โดยไม่ต้องเชื่อระบบ

ข้อมูลดิบ IoT / CSV→ SHA-256 content_hash→ เอกสารเต็มบน IPFS (CID)→ VC เซ็น Ed25519→ Hedera HCS anchor→ VCU token (HTS)

ผู้ตรวจภายนอกดึงเอกสารจาก CID มา hash ซ้ำ ต้องได้ตรงกับ content_hash ใน credential ที่ anchor บนเชน — แก้ข้อมูลจุดใดจุดหนึ่งย้อนหลัง ลายเซ็นและ hash จะฟ้องทันที

สถานะที่วิ่งผ่านระบบPDD: draft → submitted → under_validation → registered (หรือ revision_required / rejected) · Verification: draft → submitted → under_review → approved+locked → anchored
หลักการสำคัญตัวเลขเคลมทุกตัว "derive จากข้อมูลดิบ" ไม่ใช่พิมพ์มือ · เอกสารที่อนุมัติแล้วแก้ไม่ได้ (freeze + hash) · ทุกบทบาทเห็นเฉพาะปุ่มที่ตัวเองมีสิทธิ์ทำจริงบน API
ผลลัพธ์ที่ผู้ซื้อเครดิตเห็นToken ชื่อโปรเจกต์บน HashScan · จำนวน tCO₂e ตรงกับ credential · trust chain ครบตั้งแต่ PDD จนถึงการ mint
