1
Project Proponentเจ้าของโครงการ
สร้างโครงการปลูกป่าในระบบ — ใส่ชื่อ, พื้นที่ (location), วันเริ่มโครงการ (กำลังการผลิต = 0 เพราะเป็นป่าไม้) Projects → New
2
Project Proponent
เลือก Methodology (เช่น VM0047 หรือ T-VER-F-01) แล้วกรอกเอกสาร PDD ครบ A–E: ข้อมูลโครงการ, Baseline, Additionality, คาดการณ์การกักเก็บ (tCO₂e/ปี), แผนติดตาม Registration
3
Project Proponent
แนบหลักฐาน (Site Photo, Supporting Evidence, Commissioning Report) แล้วกด ส่ง PDD เพื่อตรวจสอบ Submit
4
VVBผู้ตรวจอิสระ
Validate PDD — ตรวจว่าออกแบบโครงการถูกหลัก methodology → ออก Validation Report หรือส่งกลับให้แก้ไข Validation Queue

Standard RegistryVerra

GATE 2 ติดตามผล & ทวนสอบ → ออกเครดิต

6
Project Proponent
ปลูก & ติดตามจริง — วัดการเติบโต/การกักเก็บคาร์บอนจริง (สำรวจแปลงตัวอย่าง + สมการ allometric) แล้วอัปโหลดข้อมูลเป็น tCO₂e ต่อรอบ Upload
7
Project Proponent
รวมข้อมูลเป็น ชุดทวนสอบ (ช่วงเวลา + ปริมาณ tCO₂e + หลักฐาน) แล้วส่งให้ VVB Verifications
8
VVB
Verify — ตรวจทวนสอบ, ให้ความเห็น, ขอแก้ หรือ อนุมัติ ชุดข้อมูล (ล็อกด้วย hash) Review
9
VVB
Anchor to Hedera Guardian — ออก Verifiable Credential (VC) บันทึกลง HCS topic บนบล็อกเชน
10
Standard Registry
Mint VCU Token — สร้างคาร์บอนเครดิตตาม VC ที่ผ่านการทวนสอบ → เห็นใน Token History Guardian
👀 ตรวจสอบย้อนหลังได้ (Audit) — ทุกฝ่ายดูได้:
  • PDD Document (แท็บในหน้าโครงการ) — เอกสารเต็มพร้อม content hash สำหรับตรวจความถูกต้อง
  • Trust Chain — ไทม์ไลน์: PDD ขึ้นทะเบียน → ทวนสอบผ่าน → ออก VC → Mint token
  • Token History & Audit Log — ประวัติการออกเครดิตและทุกการกระทำ
⭐ จุดเด่นของโครงการปลูกป่า (ต่างจากพลังงาน)
  • ข้อมูลติดตามเป็น tCO₂e โดยตรง (จากการวัดต้นไม้ ไม่ใช่หน่วยไฟฟ้า kWh)
  • VM0047 ใช้ Dynamic Performance Benchmark (เทียบกับแปลงควบคุม) แทน baseline คงที่
  • เลือกวิธีวัดได้ 2 แบบ: Area-based (รีโมตเซนซิ่ง) หรือ Census-based (นับต้นจริง)
